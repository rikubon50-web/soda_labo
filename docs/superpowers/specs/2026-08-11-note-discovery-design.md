# 設計書: note内発見性・導線の全面再設計

日付: 2026-08-11
状態: 承認待ち

## 背景と目的

X撤退によりSODAの読者獲得導線はnote内で完結させる必要がある。現状の実数:

- フォロワー **5人**、記事111本、総ビュー911（中央値5ビュー/記事）、スキ率27%
- **マガジン0**（テーマ別の回遊・購読導線がない）
- プロフィール文が「AI運営実験のログ」でニュースメディアとしての価値提案がない
- 固定記事・サイトマップなし。`funnel_status.md` はX前提のまま失効

スキ率27%は「読んだ人には刺さっている」ことを示す。ボトルネックは発見面。本設計はnote内の発見面（マガジン・プロフィール・固定記事・タグ・検索）を一度で整備し、以後の維持を自動化する。

決定済み: note側操作は**全部自動化**（Playwright、`note_post.py` と同じ `.browser_profile/note` セッション）。マガジンは**テーマ別3誌**。

## 成功指標

- 主要: noteフォロワー数（現在5人）。`note_metrics.py` を拡張してフォロワー数も日次記録し、週次分析で推移を追う
- 副次: 新規記事の初週ビュー（現在1〜5）、マガジン経由の回遊（定性）

## 初期整備（1回だけ実行するスクリプト群）

### 1. マガジン3誌の作成

| マガジン名 | 対象 |
|-----------|------|
| AIとマネーの定点観測 | 投資・M&A・資金調達・企業価値 |
| AIと雇用のゆくえ | レイオフ・働き方・スキル・組織 |
| AI業界の構造転換 | 企業戦略・競争・規制・技術転換 |

- 新規 `scripts/note_magazine.py` に作成機能を実装。note APIのマガジン作成エンドポイント（Web UIが叩く `/api/v1/our/magazines` 系）を既存セッションで使用。**エンドポイント・ペイロードは仮説であり、実環境の挙動を見て調整する**（note_metrics.py と同じ開発パターン。失敗時は生レスポンスを logs/errors/ にダンプ）
- 各誌の説明文（スクリプト内定数、この文言で確定）:
  - AIとマネーの定点観測: 「AIに流れるお金を毎朝定点観測。投資・M&A・資金調達を『なぜ』で読む。」
  - AIと雇用のゆくえ: 「AIは誰の仕事をどう変えるのか。レイオフ・働き方・組織の変化を毎朝追う。」
  - AI業界の構造転換: 「勝者が入れ替わる瞬間を見逃さない。AI企業の戦略・競争・規制を構造で解説。」

### 2. 既存111本の一括振り分け

- 新規 `scripts/note_backfill_magazines.py`（1回実行して役目を終える使い捨て。実行後も削除はしない）
- 分類: 記事タイトル+冒頭を Claude CLI（`soda_utils.run_claude`）に渡し、3誌のいずれか1誌に判定させる（複数該当は主題1誌のみ）。判定結果を `logs/ops/magazine_assignment.json` に保存してから、Playwright/APIで各記事をマガジンに追加
- レート: 記事間に2秒ウェイト。失敗記事は記録して継続（全体を止めない）。`--dry-run`（判定だけ）と `--limit N` を付ける

### 3. プロフィール文の更新

新文面（`note_magazine.py` の `--update-profile` で適用）:

```
毎朝8時、AIニュースを1本だけ深掘り。「何が起きたか」ではなく「なぜ起きているか」まで構造解説します。企画・取材・執筆・公開まで全部AIが運営する実験メディア。
```

- ニュースメディアの価値提案を先頭に、AI全自動運営は差別化要素として後段に残す

### 4. サイトマップ記事（固定記事）

- タイトル: 「SODAの歩き方 — 毎朝のAIニュース構造解説、どこから読むか」
- 内容: SODAの読み方（毎朝1本・構造解説・伏線回収の説明）+ 3誌の案内 + ビュー上位の代表記事5本へのリンク（`logs/metrics/` から自動選定）
- 生成はClaude CLI、公開は既存 `note_post.py`、公開後にプロフィールの固定記事（クリエイタートップのピン）に設定（Playwright）
- この記事は日次パイプラインの対象外（`content/note/` ではなく `content/drafts/sitemap.md` に置き、note_post.py に直接パスを渡す）

## 日次運用（パイプライン組み込み）

### 5. 当日記事のマガジン自動追加

- `daily_pipeline.py` の note投稿成功後に `scripts/note_magazine.py --add-today` を呼ぶステップを追加
- テーマ判定: Step 7（Secretary日次ログ）の後にパイプラインプロンプトへ「本日の記事を3誌のどれに入れるか1誌判定し `logs/daily/{ds}_magazine.txt` に誌名のみ保存」する指示を追加。`--add-today` はこのファイルを読んで追加を実行（ファイルがなければタイトルからスクリプト内でルール判定にフォールバック: 「レイオフ/雇用/人員」→雇用誌、「投資/買収/資金/ドル/円」→マネー誌、それ以外→構造転換誌）
- 追加失敗は notify_error 通知のみでパイプラインは止めない

### 6. ハッシュタグ・タイトル規則の強化（`agents/writer.md`）

現行「候補例から5つ」を以下に置換:

```
1. 大タグ2個: #AI #生成AI（固定。noteのタグページ流入用）
2. 検索ニッチタグ2個: 記事の主題で実際に検索されそうな語（例: #レイオフ #AI投資 #OpenAI #AI規制）
3. 記事固有タグ1個: 企業名・製品名など（例: #Anthropic #Gemini）
```

タイトル規則を1行追加: 「タイトルには読者が検索しそうな固有名詞または数字を必ず1つ含める（既存の執筆スタイルの範囲で）」

### 7. 導線チェックのnote化（`scripts/run_list_check.py` 書き換え、21:15 cron時刻は不変）

チェック項目をX前提の4項目から以下に置換:

1. 今日の記事が3誌いずれかのマガジンに入っているか（`logs/daily/{ds}_magazine.txt` の存在+APIでマガジン内記事を確認）
2. 今日の記事末尾にnoteフォローCTAがあるか（ローカルmdをスキャン）
3. プロフィール固定記事（サイトマップ）が設定されているか（クリエイターページAPIで確認）
4. フォロワー数の前日比を記録（`logs/ops/follower_log.jsonl` に追記）

未達項目は既存の notify_error 経路で通知。`funnel_status.md` はこの4項目のnote版ステータス表として全面書き換え。

### 8. `note_metrics.py` の拡張

- クリエイターAPI（`/api/v2/creators/soda_labo`）からフォロワー数を取得し、日次JSONに `"followers": N` を追加。分析・週次はこの値を推移として参照可能に

## 手動でお願いすること（ユーザー作業）

- noteアカウント設定のTwitter連携解除（プロフィールに@SODA_LABOリンクが残っているため）

## スコープ外

- 有料コンテンツ・メンバーシップ（数字が伸びてから）
- 週1ストック記事の自動生成（次プロジェクト候補）
- note以外への配信

## エラー処理方針

既存踏襲。note側操作の失敗はすべて「通知して継続」。初期整備スクリプトは再実行安全（振り分け済み記事はスキップ）にする。

## 検証方法

1. **実装中**: 各note操作はまず `--dry-run`/`--limit 1` で実挙動を確認してから全量実行（note_metrics.py開発と同じ実物合わせパターン）
2. **初期整備後**: クリエイターページを実際に開き、3誌・振り分け・新プロフィール・固定記事を目視確認（スクリーンショット取得）
3. **翌日**: パイプライン完走後、当日記事がマガジンに入り、21:15チェックが4項目パスすることをログで確認
