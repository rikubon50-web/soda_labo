# X ニュース速報×構造解説 戦略再設計

作成日: 2026-05-09

---

## 背景・問題定義

note は伸びている（noteマネー等の媒体に取り上げられる水準）一方で、X はインプレッション数で停滞している。直近2週間の X 投稿は IMP 0〜3 が大半、唯一 5/07 昼の Anthropic-Blackstone 構造解説のみ 35 IMP に到達した。

### 現状診断（一行）

現状 IMP≈3 はフォロワー基数要因が主、コンテンツ要因は二次。型を遵守しても短期的に IMP は大きく動かない可能性が高い。だからこそ初期はプロセス KPI で「正しい運用が回っているか」を先に確認する必要がある。

### 問題の構造

1. **軸の混在**：ニュース解説／Day 記録／AI それって本当？ が並走し、アカウントが何の場所か不明瞭
2. **連結前提の投稿構成**：朝予告→昼解説→夜 CTA がフォロワー少ない段階では機能しない
3. **note 役割と曖昧な分担**：X が note のチラシ置き場になっており、X 単独の本編価値が弱い
4. **外部 URL の毎回添付**：アルゴ的に不利、かつ単独完結性を損なう

## 戦略の核

### X と note の役割分担

| 媒体 | 役割 | 対象範囲 | 頻度 |
|------|------|---------|------|
| **X** | ニュース速報＋一行解釈（速度・量・幅） | AI ニュース全般（モデル発表・資金調達・規制・労働・ツール・買収など幅広く） | 1日3本 |
| **note** | 深掘り（深さ・保存価値） | 「AI×お金・雇用・構造転換」**3テーマに限定** | 毎日1本 |

### note と X のニュース選定の関係（並走モデル）

両媒体は同日並走で運用する。note 化選別ではなく、それぞれの対象範囲で独立にニュースを選ぶ。

- note：その日のニュースから「AI×お金・雇用・構造転換」3テーマに**該当するもの1本**を選んで深掘り
  - 該当基準：大型投資・合弁・M&A／大規模レイオフ×AI活用／業界構造の転換／競合複数社の同週同方向の動き
  - 該当ニュースが当日になければ、過去3〜7日のニュースから「今振り返る」型で1本選ぶ（note のスロー日対策）
- X：AI ニュース全般から3本選ぶ。**そのうち1本は note と同じニュースを構造解説型ショート版で扱う**（夜の枠に置き、CTA で note 本編に誘導）。残り2本（朝・昼）は別ニュース。
- 純粋な技術発表・ベンチマーク・ツール紹介など3テーマに該当しないニュースは X だけで完結させる（note 化しない）

既存の AI それって本当？／Day 記録は X・note ともに新規生成を停止する。

## 投稿フォーマット（構造解説型・標準）

### テンプレート

```
[1] ニュースの事実を1〜2文で提示（数字＋主体を含める）
[2] 「なぜか」「これは何の話か」を箇条書き2〜4点で構造化
[3] 一行で示唆（読者が考えたくなる形で締める）
```

### 例

```
AnthropicがOpenAIのARRを抜いた。$30B対$24B。

なぜか。性能勝負ではなく、選ばれる基準が変わった。
・大企業：安全性・コンプラ適合性
・個人：速度・UX

軸が分かれた瞬間、ChatGPTの先行優位は通用しなくなった。
```

### ルール

- 文字数：140〜400字
- 外部 URL の添付ルール：
  - 添付するのは note 格上げ対象（資金・雇用・構造転換）に該当するニュースのみ、かつ週1〜2回まで
  - それ以外は本文中に出典名を文字列で明記する（例：文末に `— CNBC報道` `— Anthropic公式` と添える形）
- 単独完結を絶対条件にする：他の投稿に依存する文脈（「今朝の続き」「昼に整理する」など）禁止
- SODA_LABO の内輪表現禁止：「Day N」「うちの AI 社員」「実験ログ」など初見不明語を使わない
- 結論を投稿内に必ず置く。「続きはあとで」「note に書く」だけの予告型は禁止

## 1日3本の運用

### 構成

- 朝・昼・夜でそれぞれ**別のニュース**を1本ずつ取り上げる
- 3本とも構造解説型・単独完結
- 夜の1本はその日の note 記事と同じニュースを X 用ショート版で扱う（X 単独でも完結、末尾 1 行で note 誘導）
- 既存の Day 記録、AI それって本当？ シリーズは廃止

### note 送客

- 夜の投稿（3本目）末尾に毎日 note CTA を1行追加（note も毎日公開のため）
- 朝・昼の投稿には note CTA を入れない（X 単独完結を優先）

### スロー日対策（優先順位ルール）

質 > 本数 を絶対の優先順位として、以下の代替策を順番に取る：

| 段階 | 対応 |
|------|------|
| A | 当日の新規ニュースが3つ揃わない場合 → 過去3〜7日のニュースを「新しい角度」で構造解説し直す（同一ニュースの再投稿は NG） |
| B | 過去ニュースでも届かない場合 → 過去1ヶ月の重要ニュースを「今振り返ると」型で再解釈する |
| C | それでも厳しい場合 → 本数を 2本／1本に落とす（最低1本/日は死守） |

**禁止**：ネタ不足を理由に Day 記録・雑記・予告型に逃げること。質を落とすくらいなら本数を落とす。

## KPI と振り返り

### KPI 構成

| 区分 | 指標 | 評価方法 | 目標 |
|------|------|---------|------|
| 結果系 | 1投稿平均 IMP | 数値 | 4週後 20+（現状≈3） |
| 結果系 | フォロワー増減 | 数値 | 4週後 +10〜30 |
| 結果系 | note 誘導日のフォーム到達数 | 数値 | 4週後 累計 5+ |
| プロセス系 | 型遵守率（構造解説型テンプレ準拠） | 0/1判定×投稿数 | 90%以上 |
| プロセス系 | 投稿本数達成率（1日3本投下） | 0/1×日数 | 90%以上（スロー日対策Cで本数を落とした日も「ルール順守＝達成」とみなす） |
| プロセス系 | 禁止表現混入率（予告型・Day 記録・内輪語） | 違反件数 | 0件/週 |

## 想定リスクと回避策

| リスク | 回避策 |
|--------|-------|
| 1日3ニュースの供給が安定しない | スロー日ルール（A→B→C）で対応、本数を死守しない |
| 構造解説型に書き手が慣れず質がバラつく | 5/17 のプロセス点検で型遵守率を測定、低ければ writer.md を再調整 |
| 当日 note 用の3テーマ該当ニュースが出ない | note 側スロー日対策（過去3〜7日からの「今振り返る」型）で対応 |
| 3テーマ判定が運用上ぶれる | 該当基準を winning_topics.md に固定し、毎週日曜のレビューでチェック |
| IMP が4週後も伸びない | 6/7 評価時にコンテンツ要因／フォロワー基数要因を切り分け、後者が主因なら別の露出経路を再検討 |
