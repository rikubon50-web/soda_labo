## 北極星

**目標=マネタイズ、そのマイルストーン=noteフォロワー増加。** システムの全要素は「週次のフォロワー純増」に寄与するか否かで残否を決める（ユーザー決定 2026-08-13）。

## 設計原則（監査の実証から）

1. 公開する記事はすべて「伸びる型」だけにする — 週間まとめ（実証済み勝ち型）・実録（スキ率とコメントの実績）・大ニュース即応深掘り（全期間最高131ビューの源泉）
2. 誰にも読まれない産出物を作るジョブは廃止する（演劇の禁止）
3. フィードバックは1本の週次レビューに集約し、確実に翌週の制作に接続する（接続をファイルで実装し、grepで検証可能にする）
4. 沈黙型失敗を検知する仕組みを持つ（監査で4ヶ月・16週・2.5ヶ月の無検知空白が実証されたため）
5. 読者ターゲットは実測に合わせて「27〜35歳の発信・副業・AI活用層」に修正（「20代」は114日間未検証の願望と監査判定）

## 変更1: 平日のイベント即応制

daily_pipeline の平日モードを変更する。Step 0（ニュース収集）と Step 1（CEO）はそのままだが、CEOの判断を「今日のトップニュースを選ぶ」から「**今日、即応深掘りに値する大ニュースがあるか**」のゲート判定に変える。

- **出す基準**（プロンプトに明記): 業界構造を変える規模のイベント（大型買収・大規模レイオフ・主要モデル/製品の発表・重大規制）で、翌日整理型の深掘り（Kimi K3型=実測131ビュー）が書けるもの。「読者がSODAで検索・回遊しに来る日」だけ出す
- **出す日**: 現行の全工程（取材→執筆→批評→公開→マガジン追加）をそのまま実行
- **出さない日**: 記事を書かず、`content/news/{ds}_memo.md` に非公開の素材メモ（その日の主要動向3行+perspectives接続候補）だけ保存して終了。note公開なし。目安は週2〜3本公開
- 土日モードは現行維持（変更しない）

## 変更2: 統合週次レビュー（weekly_analysis を改組）

日曜21:30の1本に、廃止する7ジョブの「本当に必要だった機能」を吸収する:

1. 週次数字レビュー: フォロワー純増（北極星）・記事別ビュー・土日vs平日比較・商品化トリガー判定（現行機能維持）
2. **翌週方針の決定**: 旧朝会議のCEO判断を週1に。結果を `docs/weekly_direction.md` に保存し、**daily_pipeline の事前読み込みに追加**（接続をファイルで実装）
3. 勝ちパターン更新: `audience/winning_topics.md` の更新をここに移し、昇格基準を機械化（**実測100ビュー以上のみ「勝ち」と記録**。数字インフレの禁止を明記）
4. 導線チェック: 旧 run_list_check の4項目を週1で確認
5. コンテスト・お題チェック: WebSearch で note.com/contests を確認し、翌週の記事で相乗りできるものを weekly_direction.md に記載
6. ペルソナ検証: 実測データから読者仮説（27〜35歳発信・副業層）の検証メモを audience/personas.md に追記

## 変更3: 沈黙検知 `scripts/health_check.py`（新設・毎日9:00）

- 前日に期待される産出物の存在を確認: `logs/metrics/{昨日}.json`（毎日）/ `content/note/{昨日}_*.md` または `content/news/{昨日}_memo.md`（毎日どちらか必須）/ 日曜なら `logs/weekly/{当日}.md`
- 欠けていれば notify_error でメール通知（既存経路）
- `.env` に `HEALTHCHECK_URL` があれば成功時にping（外形監視。healthchecks.io 等の無料サービス登録はユーザーの任意・後日でよい。未設定ならスキップ）
- Claude呼び出しなしの純Pythonスクリプト（軽量・壊れにくい）

## 変更4: 汚染・遺物の浄化

- `audience/winning_topics.md`: X時代の「確定勝ちパターン」（実在しないファイル参照込み）を削除し、実測100ビュー基準で書き直す
- `audience/personas.md`: ターゲットを「27〜35歳の発信・副業・AI活用層（検証中仮説）」に更新。「20代」記述を修正
- `docs/content_strategy.md`: 本設計の内容（イベント即応制・北極星・ターゲット修正）に全面改訂

- `funnel/email/` のX誘導文言を除去、`experiments/` の4月から放置の4ファイルは `experiments/archive/` へ移動
- 廃止ジョブのスクリプト（run_meeting / run_post_analysis / run_idea_mining / run_product_memo / run_product_meeting / run_lead_funnel_check / run_list_check）は削除（git履歴に残る）。フォロワーログ追記機能（旧list_check内）は weekly ではなく **note_metrics 側に移設**（毎日22:30に確実に1行追記）

## 変更しないもの

- 土日モード（まとめ・実録）・取材/批評/視点の品質工程・マガジン/発見性まわり・note_post/note_magazine/note_metrics の配信骨格・商品トリガー基準（50人 or 週300ビュー）・crontabのバックアップ運用

## ユーザーへの申し送り（任意・後日）

- Macのスリープ設定（`pmset` は sudo が要るため手動）: 電源接続時スリープしない設定を推奨
- healthchecks.io 等の外形監視の無料登録（登録したら `.env` に `HEALTHCHECK_URL=...` を1行追加するだけ）

## 検証方法

1. **実装直後**: crontab が5本構成/廃止スクリプトの参照ゼロ/平日プロンプトにゲート判定・素材メモ分岐/weekly_review プロンプトに6機能/health_check の3ケース（正常・欠損・日曜）動作
2. **初回サイクル**: 平日のゲート判定が機能するか（出す/出さないの判断とメモ生成）、8/15(土)まとめ・8/16(日)実録+初の統合週次レビュー完走
3. **週次**: フォロワー純増が唯一のKPIとして weekly レポート冒頭に出ること
