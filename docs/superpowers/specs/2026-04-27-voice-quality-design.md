# 設計書：記事生成の自然さ向上（Voice Quality）

**日付：** 2026-04-27  
**スコープ：** 記事生成パイプライン全層（プロンプト・エージェント・パイプライン）  
**アプローチ：** 声の定義ファイル新設 + 各層への参照統合

---

## 背景と課題

現在の記事生成パイプライン（Step 0-7）で出力される文章は、構成・内容の面では一定の質を保っているが、以下の3点が複合的に「AI臭さ」として感じられる：

1. **文章の型が予測通りすぎる** — 「3点あります」「まとめると」など番号と定型まとめへの依存
2. **語感が自分の言葉ではない** — よそよそしさ・ていねいすぎる整合感
3. **本音・迷い・留保が薄い** — うまくいった話だけでなく、内的な揺れが出ていない

---

## 設計方針

`docs/voice_guide.md` を「声の基準書」として新設し、これを Single Source of Truth にする。Writer・Editor・パイプラインがそれぞれこのドキュメントを参照することで、各層に一貫した「自然さの基準」を浸透させる。

---

## アーキテクチャ

```
docs/voice_guide.md        ← 新設。NG/OK例・自然さの定義を集約
       ↓ 参照
agents/writer.md           ← 更新。冒頭にvoice_guide参照を追加
agents/editor.md           ← 更新。自然さチェックリストセクションを追加
       ↓ 参照
src/pipelines/daily_pipeline.py  ← 更新。Step4/5/6の指示を強化
  - 事前読み込みにvoice_guide.mdを追加
  - Step4（Writer）：生成前にvoice_guide確認を義務化
  - Step5（Editor）：編集メモに自然さ確認項目を追加
  - Step6（CEO）：採点基準に自然さ基準を追加
```

## 各ファイルの変更詳細

### 1. `docs/voice_guide.md`（新設）

4ブロック構成：

**① 自然さの定義**
「書いた人間の迷いや手触りが残っている」こと。整いすぎた文章はAI臭い。

**② AI臭いパターン一覧（NG → 修正例のペア）**
- `「3点あります」` → 番号を振らず次の文でいきなり語る
- `「まとめると〜」` → 締めは余韻か問い。まとめない
- `「〜と言えるでしょう」` → 断定か削除
- `「〜を意識することが大切です」` → 説教。削除
- `「〜の時代において」` → 前置き削除、本論から始める
- 箇条書きで並べて最後に見解なし → 箇条書き後に自分の一文を必ず入れる

**③ 自然な文章のOK条件**
- 途中に「でも」「ただ」など自分の中の揺れが見える
- 具体的な固有名詞・数字・日付がある
- 「まだわからない」「そうとも言えない」などの留保が入っている
- 読み上げて詰まらない

**④ 書く前の自己確認リスト（3問）**
1. この文章、自分が実際に経験したことか？
2. 「で、読者は何をする気になる？」
3. これを友人に口頭で話したら、同じ言い回しになるか？

### 2. `agents/writer.md`（更新）

冒頭に追加：

```markdown
## 文章を書く前に必ず実行すること

docs/voice_guide.md を Read tool で読み込む。
生成した文章を voice_guide の「AI臭いパターン」に1つずつ照合し、
該当箇所があれば修正してからファイルに保存する。
```

既存のルール（構成・文字数・フォーマット）は変更しない。

---

### 3. `agents/editor.md`（更新）

チェックリストに「自然さ確認」セクションを追加：

```markdown
### 自然さ確認（voice_guide.md 照合）
- [ ] docs/voice_guide.md を Read tool で読み込んだか
- [ ] AI臭いパターンが残っていないか（1つずつ照合）
- [ ] 「まとめると」「〜点あります」「〜が大切です」が残っていないか
- [ ] 途中に「でも」「ただ」「まだわからない」などの揺れが1箇所以上あるか
- [ ] 読み上げて詰まる文がないか
```

既存の3セクション（トーン確認・構成確認・文章確認）はそのまま維持し、4つ目として追加する。

---

### 4. `src/pipelines/daily_pipeline.py`（更新）

**事前読み込みリストに追加：**
```
7. docs/voice_guide.md — 声の基準書（WriterとEditorは必ず参照すること）
```

**Step4（Writer）に追加：**
```
文章を生成する前に docs/voice_guide.md を確認し、
AI臭いパターンが出ていないかを照合してからファイルに保存すること。
```

**Step5（Editor）の編集メモに追加：**
```
- 自然さ確認: voice_guide照合 ✅/❌ | AI臭いパターン修正箇所（あれば列挙）
```

**Step6（CEO採点）の採点基準に追加：**
```
- 自然さ：voice_guide の AI臭いパターンが残っていないか。
  人間が書いた手触りがあるか（迷い・留保・固有の具体性）。
  残っている場合はスコアを1点減点する。
```

- 生成記事に「まとめると」「3点あります」「〜が大切です」が出なくなる
